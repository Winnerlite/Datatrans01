How It Works — Personal Notes

Everything about route prices, the two tiers, and how they're used. Written for me, on my worst-forgetting day.

Read this when: you forget what "Est. Base Fare" means, why a route shows one price but not another, how to add a new direct route, or how to onboard a new API client.

1. The Two Tiers

Every route in the calculator uses one of two price sources:

Direct Fare

The real, verified price. Comes from the routePrices object in ngr.json.

Example: routePrices["Lagos-Onitsha"]["ABC Transport"] = 29120

Est. Base Fare

A fallback estimate. Uses the company's basePrice field, which is the same for every route.

Example: transportCompanies["ABC Transport"].basePrice = 23904

2. Which Tier Gets Used?

The calculator checks in this order:

  1. 1. Does routePrices[from-to] exist in ngr.json?
  2. ✓ YES → Show only Direct Fares. Estimates are skipped.
  3. ✗ NO → Show Est. Base Fare for every company that operates in BOTH states.
Rule of thumb: if you see a green "Direct Fare" tag, that number is real. If you see an amber "Est. Base Fare" tag, it's the company's default base price — same number regardless of route.

3. Why Est. Base Fare is Rough

Each company has ONE basePrice value. It doesn't change by route.

So if ABC Transport has basePrice: 23904, then:

Lagos → Abuja₦23,904
Lagos → Kano₦23,904
Lagos → Port Harcourt₦23,904

Same price everywhere. This is why Direct Fares matter — they override this guess with a real value.

Don't show basePrice as "real": always label it "Estimated" in the UI so users know it's a guess.

4. How to Add a New Direct Route

Edit ngr.json and add an entry inside routePrices:

"routePrices": {
  "Lagos-Onitsha": {
    "ABC Transport": 29120,
    "God is Good Motors": 36400,
    "Chisco Transport": 25480,
    "GUO Transport": 35490,
    "Peace Mass Transit": 22750
  }
}
After saving: reload the site, search Lagos → Onitsha. Every company listed above will now show "Direct Fare" instead of "Est. Base Fare".
Watch out: the route key must match EXACTLY. Lagos-Onitsha ✅ · Lagos - Onitsha ❌ (spaces) · lagos-onitsha ❌ (lowercase)
Naming rule: the key is always FromState-ToState with a hyphen, no spaces. Direction matters — Lagos-Onitsha and Onitsha-Lagos are two separate entries.

5. The Company Name Matching Problem

The same company can appear with different names in routePrices vs transportCompanies. This causes silent mismatches.

Example of a real mismatch in the data:

In routePrices:

"Young Shall Grow"

In transportCompanies:

"The Young Shall Grow Motors"

Fix: the ALIASES object in calculateTrip() maps variants to the canonical name:

const ALIASES = {
  "Young Shall Grow": "The Young Shall Grow Motors",
  "The Young Shall Grow": "The Young Shall Grow Motors",
  "The Young Shall Grow Motors": "The Young Shall Grow Motors",
  "GIGM": "God is Good Motors",
  "Nsik": "Nsik Motors (AKTC)"
};
When adding a company: make sure the exact string in routePrices matches a key in transportCompanies, or add an entry to ALIASES.

6. The Algorithm (Simplified)

function calculateTrip() {
  // 1. Try direct route
  if (ngr.routePrices[from + '-' + to]) {
    return ngr.routePrices[from + '-' + to];  // ← Direct Fares
  }

  // 2. Fall back to estimates
  const shared = ngr.states[from].companies
    .filter(c => ngr.states[to].companies.includes(c));

  return shared.map(c => ({
    name: c,
    price: ngr.transportCompanies[c].basePrice || 25000  // ← Est. Base Fare
  }));
}

That's the whole thing. Two branches. No AI, no distance, no terminal check — just route presence, then base price fallback.

7. CORS — Who Can Call the API

Current whitelist in the server:

const allowedOrigins = [
  'https://www.intercityprices.com.ng',
  'https://intercityprices.com.ng',
  'http://localhost:3000',
  'http://localhost:5500'
];
What this means: only your own domain (and localhost for testing) can call the API from a browser. Any other site gets blocked.
For the client tester page: host the tester on YOUR domain (/api-test.html) and give clients the URL. They see it working live without needing to add their domain to the whitelist.
Server-side calls are unaffected. CORS is a browser-only restriction. If a client calls the API from their backend (Node, Python, PHP), it works regardless of the whitelist.

8. Onboarding a New API Client

Repeat every time

When a paying client wants to integrate the API from their own website, follow these steps in order.

Step 1 — Ask for their exact domain(s)

Get the full origin, including protocol. Ask for both production and staging if they have them.

✅ Correct format:

https://clientdomain.com
https://www.clientdomain.com
https://staging.clientdomain.com

❌ Wrong format:

clientdomain.com // no protocol
*.clientdomain.com // wildcards not allowed
clientdomain.com/ // trailing slash breaks match

Step 2 — Add them to the whitelist

Edit the allowedOrigins array in every endpoint handler. Add one line per domain. 

const allowedOrigins = [
  // ─── Your own domains ───
  'https://www.intercityprices.com.ng',
  'https://intercityprices.com.ng',

  // ─── Local dev ───
  'http://localhost:3000',
  'http://localhost:5500',

  // ─── Client: Acme Travels (onboarded 2026-05-19) ───
  'https://acmetravels.com',
  'https://www.acmetravels.com',
  'https://staging.acmetravels.com'
];
Why the comment? Six months from now you'll forget who "acmetravels.com" is and whether it's still paying. Add the date and client name so you can clean up safely.

Step 3 — Update every endpoint handler

If your server has multiple files (/api/search.js, /api/transport.js, etc.), you must add the origin to each file that runs allowedOrigins.

Common mistake: adding the client to only one endpoint and then wondering why half their requests fail. If you have 4 endpoints, they need to be in all 4.
Better long-term fix: put allowedOrigins in a shared file (lib/cors.js) and import it everywhere. One edit, all endpoints updated.

Step 4 — Redeploy

Push the change to production. On Vercel, this is just git push. Wait for the deploy to go live (check the dashboard).

Step 5 — Tell the client to test

Send them this exact message:

"Hi [Name] — your domain has been whitelisted. Please open your browser console on your site and try calling:

fetch('https://www.intercityprices.com.ng/api/search?q=Lagos').then(r => r.json()).then(console.log)

If you see JSON in the console, you're good to go. If you see a CORS error, send me a screenshot of the Network tab and I'll sort it."

Step 6 — Confirm and log it

Once they confirm it works, add them to the client log below.

📒 Client Whitelist Log

Keep this updated. Remove entries when a client leaves.

Client Domain(s) Date Added Status
No clients onboarded yet — add a row when you do.
Copy this table into a Google Sheet if you get more than 5 clients. Easier to maintain than editing HTML.

🚪 When a Client Leaves

  1. Remove their domain from allowedOrigins in every endpoint handler
  2. Redeploy
  3. Mark them as "Removed" in the client log with the removal date
  4. If they had a dedicated API key (future feature), revoke it
