Authentication

Send your key in the x-api-key header on every request. Each key is tied to the website domain you whitelist when it is issued.

Server-side requests need an Origin header. Browsers add Origin automatically and do not let you set it yourself. Scripts running on a server (cURL, Node.js, PHP, Python) must send it, with the exact domain you whitelisted.

Endpoints

Every operator follows the same pattern: /api/{provider}. Base URL: https://intercitypricesbookings.cybercatclientcreator.workers.dev

Fetch trips

GET /api/{provider} returns an array of upcoming trips with fares and seat availability.

Create a booking link

POST /api/{provider}/generate-link takes a trip ID and an array of seat numbers. On success it returns formUrl. Redirect your customer there to enter passenger details and pay.

Errors and limits

StatusMeaningWhat to do
401Missing or invalid API key.Check the x-api-key header.
403Origin is not whitelisted.Send the exact whitelisted domain in Origin.
404Unknown operator or trip.Check the provider name and trip ID.
429Rate limit exceeded.Wait and retry with backoff.

Rate limits are set per key and confirmed when your key is issued. Seat availability comes from each operator in real time, so re-fetch trips before creating a booking link.
